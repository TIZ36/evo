# Design Brief · evo DSH 插件界面（整体重做）

设计上下文见 `../.impeccable.md`。本文只讲这次重做要做成什么样，不含实现代码。

---

## 1. Feature Summary

evo 在 DSH web 客户端里的完整界面，整体重做。它要让唯一的日常用户在几秒内确认「evo 从刚才那轮对话里蒸馏出了什么」，并在怀疑 agent 行为跑偏时能查到历史上记过什么。当前版本的核心失败是：列表每行只有 `kind + 标题 + 时间`，正文必须点进详情才看得到——**看得见记忆的存在，看不见记忆的内容**，信任感没有兑现。

## 2. Primary User Action

**扫一眼就读到 evo 最近记住的内容本身。**

不是"找到某条记忆"，不是"管理记忆库"。第一屏必须直接呈现正文，而不是呈现一个需要再点一次才有信息的索引。

## 3. Design Direction

沉静、可核查、有记账感；像翻实验笔记而不是看仪表盘。全部继承 DSH token，不引入自己的字体与色板——**笔记人格靠排版结构建立**：

- 受控行长（正文 ~68ch）、行高 1.6、正文与元数据之间有明确字号断层（≥1.25 比例）
- 左侧一条 1px hairline 时间轴 + 节点圆点做时序骨架（**不是**彩色 side stripe——那是被明令禁止的 AI 套路）
- 分组标题是日期/会话本身，不是卡片标题；**不用卡片包裹任何东西**
- 元数据全部 tabular-nums，小号、三级色
- 胶囊 mark 保留为唯一品牌资产，珊瑚 accent 只在 busy 时出现，总用量 <5%

## 4. Layout Strategy

Settings→Memory 拆成**两个模式**，解掉「笔记气质」与「上千条密度」的矛盾。

### 模式 A · Journal（默认落地）

回答"**刚刚记了什么**"。垂直时间流，最新在上，按天（或会话）分组。

自上而下：

1. **页头**：胶囊 mark + "Memory" + 数据库路径（弱化，三级色，可截断）+ 右侧动作（Refresh / Consolidate / Re-import）
2. **In context 带**：一条常驻的窄条，说明「当前会话的 scope 链上有 N 条会进入下一轮上下文」，可展开看到具体是哪几条。这是四种缺失里最独特的一条，也最能兑现信任感。
3. **时间流**：按天分组。每条记忆是**一段**而不是一行：
   - 第一行：kind 小标签（中性、大写、字距——**不给五色**）+ 标题
   - 正文摘录 **2–3 行**，超出省略（这是整个重做的关键改动）
   - 尾行：scope · 来源（`session a1b2 · turn 12`）· 被召回 N 次 · 相对时间
   - 整段可点进详情
4. 滚到底加载更早的天，不一次拉全部（当前 `limit=300` 一次性拉取要改）

### 模式 B · Library（检索时进入）

回答"**我以前记过啥**"。用户一旦在搜索框输入、点 kind 筛选、或在 scope 树选中一个节点，视图切到密集列表。

- 左：scope 树（保留现有层级结构与计数）
- 右：密集列表——每行 kind + 标题 + 单行正文摘录 + scope + 时间。行高比 Journal 紧一档
- 顶部有明确的「回到 Journal」路径 + 当前筛选条件的可移除 chip

**上千条的处理**：Library 必须分页或虚拟滚动，服务端按 scope/kind/text 过滤，不在前端 filter 全量数组（当前实现是前端 filter）。

### 详情视图

**溯源提到最前面**，不再埋在 `dl` 里。详情页顺序：kind + 标题 → **一句溯源句**（`2026-08-14 从 session a1b2 第 12 轮蒸馏 · 此后被召回 7 次`）→ 正文全文（~68ch 行长，`pre-wrap`）→ tags → 折叠的原始字段（id / path / runtime / confidence）。

### Composer chip / dock

- **chip**：胶囊 mark + `evo`。idle 时无边框透明，几乎不存在。
- **新增：reflect 完成后的一次性回执**。busy 结束时 chip 短暂显示本轮增量（如 `+2`），~2.5s 后淡回 idle。这是把"刚记了什么"推到用户眼前的**最低成本手段**，也是"看不出记住了什么"这个痛点在 composer 侧的答案。
- **dock**：只在 reflecting 时挂载，保持现状。idle 零垂直占用。
- 不做浮层。不在 chip 上展开第二套列表。

## 5. Key States

| 状态 | 用户需要看到 / 感到 |
|---|---|
| **首次安装、库为空** | 不是"暂无数据"。要说清 evo 的工作方式：「evo 会在每轮对话结束后蒸馏记忆。完成一轮，它就会出现在这里。」教接口，不只是报告空。 |
| **Journal 加载中** | 骨架而非 "Loading…" 文字——用户已经知道要来的是什么形状的东西。 |
| **正在 reflecting** | 胶囊填充回抽再充满（现有动效）；dock 行出现；Journal 顶部可预留一条"正在蒸馏本轮"的占位段。 |
| **刚 reflect 完** | chip 上的 `+2` 回执；Journal 顶部新条目带一次淡入（不是持续高亮）。 |
| **服务不可达** | **显性**。chip 转错误色 + tooltip 说明；Settings 页顶部 role="alert" 横幅带具体错误。绝不静默装作健康。 |
| **筛选无结果** | 说清是筛选造成的，并给一键清除筛选的出口。 |
| **单个 scope 为空** | 区分"这个 scope 还没有记忆"与"整个库为空"，文案不同。 |
| **上千条** | Journal 分批加载不卡；Library 分页/虚拟滚动；计数用 tabular-nums 不跳动。 |
| **consolidate 进行中 / 完成** | 按钮进入 pending；完成后给出 `before → after` 的实际变化，而不是静默刷新。 |
| **prefers-reduced-motion** | 胶囊停止扫动但**保留珊瑚填充色**（状态仍可读）；淡入动效关闭。现有实现已做，保留。 |

## 6. Interaction Model

- **入口**：composer chip 点击 → DOM 驱动打开 Settings → 点中 "Memory" 导航行。全链路失败关闭（fail closed）——任一步找不到就什么都不做，tooltip 仍然报告状态。
- **模式切换是隐式的**：输入搜索 / 选 kind / 选 scope 自动进 Library；清空筛选或点"回到 Journal"退回。用户不需要学两套心智模型，只需要"我在找东西"和"我在看最近"。
- **展开优于跳转**：Journal 里的一段点击后，优先考虑就地展开全文，而不是整页切换到详情——减少来回。整页详情保留给从 Library 进入的情况。
- **动作按钮有层级**：Consolidate 是唯一带 accent 的（也是唯一有破坏性的），Refresh / Re-import 是 ghost。Re-import 在非 project scope 下 disabled 并用 title 说明原因（现状已如此，保留）。
- **轮询节奏**：idle 8s / busy 1.5s（现状合理，保留）。
- **键盘**：所有行是真 `button`，focus-visible 有可见轮廓（现状已做）。Library 列表应支持上下键遍历。

## 7. Content Requirements

- **空态（全库）**：`evo 会在每轮对话结束后蒸馏记忆。完成一轮，它就会出现在这里。`
- **空态（筛选）**：`没有匹配的记忆。` + `清除筛选`
- **错误**：`记忆服务不可达 — {具体错误}`。必须带原始错误，这是个开发者自用工具。
- **chip tooltip**：idle `root 12 · cwd 43 条在上下文中`；busy `正在把这轮蒸馏成记忆…`；error `记忆服务不可达`
- **chip 回执**：`+2`（本轮新增条数）
- **溯源句**：`{日期} 从 session {id前8} 第 {turn} 轮蒸馏 · 此后被召回 {n} 次`；workspace 导入的则是 `从 {path} 导入`
- **kind 标签**：`fact` `preference` `constraint` `procedure` `skill` —— 大写、字距、中性色，**不给颜色**
- **动态范围**：标题长度无上限（要能截断）；正文可以很长（详情页要 `overflow-wrap:anywhere`）；scope id 是绝对路径（要中间截断或只显示 basename）；数据库路径很长（页头要能截断）

## 9. Open Questions（实现时需要解掉）

1. **"下一轮会注入哪些"没有对应后端能力。** 现有 `/memories?scopeKey=` 只能按 scope 近似，不等于实际召回集。要么接受近似（并在文案上说明是"scope 链上的候选"），要么加一个 `/context` 端点。**建议先做近似，文案诚实。**
2. **Journal 分组按天还是按会话？** 按天更像日志，按会话更能回答"刚才那轮"。倾向按天分组、组内按会话聚簇。
3. **DSH Settings 面板的实际可用宽度未测。** 当前硬编码 `max-width:760px`，需实测后定；Library 的左树+右列表在窄宽度下要能塌成单栏。
4. **只读带来的"看得到改不了"焦虑。** 这轮不做写操作是已决定的，但发现记错时用户完全没有出口。建议详情页提供"复制 id"，让用户能在 CLI 侧处理——成本极低。
5. **服务端过滤未实现。** 现在 `text` / `kind` 是前端 filter 全量数组，上千条会退化。Library 模式依赖服务端过滤，`/memories` 已支持 `kind`/`text`/`tags` 参数，前端改调用即可，但分页参数（offset/cursor）**目前没有**，需要加。
